# #605 re-baseline: what moved on the existing queries

The fixture grew from 27 books / 98 queries (old baselines) to 32 books / 105 queries. Five self-authored back-matter books (128–132) were added, with seven `back-matter-trap` queries. Every number below is on that fixture [27-book → 32-book fixture], macOS, transformers.js 4.3.2. Existing labels were never edited.

The 294 existing rows (98 queries × 3 modes) are compared per tier. Changes have two sources:
- **New books entering candidate sets.** This is the only source of Hit@1 breaks.
- **The matter-kind ranking:**
  - in library scope, a book is represented by its best body chunk;
  - strong front/back matter never enters the rerank pool;
  - in book scope, a weak front chunk competes on its rerank score.

## Causes of every Hit@1 break

How the causes were found:
- **Hash tier:** bisected without the model. The base code (`dae346c3` `src/`) with the new fixture reproduces every hash break, and HEAD code without books 128–132 reproduces none. Adding one new book at a time names the book.
- **On and fusionOnly tiers:** every break below has a new book at rank 1, represented by a body chunk.

## Front-matter-trap

- `fmt-02` (book 116) went first-place → second in the first freeze run (`0a84f460`), on/hybrid and on/vector. The cause was a weak front chunk: praise + contents + foreword, rerank 0.883 vs the body passage's 0.8718. Stopped and reported on #605.
- Artem decided that front matter holding a contents block is strong (0e3adf14). In this freeze run `fmt-02` is back at rank 1.
- `fmt-04`..`fmt-06` (book 117, on/hybrid and on/vector): the weak preface chunk `@0-1963` now ranks second, behind the unchanged rank-1 body passage. A weak preface competes on its rerank score in book scope by design.
- Every `fmt-*` Hit@1 equals the old baselines in every tier.
